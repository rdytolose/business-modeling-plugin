# IDEF0: JSON → сайт → Ramus

Сайт: https://idef0.wakl3.com/. Профиль этого навыка: экспорт файла модели
для «Ramus на Java: 20 и новее», итоговые `.rsf` и `.json`.
Пользовательский запрос на IDEF0 по этому навыку задает предпочтительный
сценарий. Разрешение исходного автора проекта от 11.10.2026 не является
разрешением другого пользователя передавать сторонние материалы: учитывать
его текущий запрос и ограничения среды. Для обычной разрешенной выгрузки
не требовать повторных подтверждений каждой кнопки.

1. Прочитать README.md, IDEF0_RULES.md, JSON_CONTRACT.md и с. 21–36 книги.
   Определить реальные исходные данные, цель, границы, точку зрения и автора.
   Создать модель по текущему описанию; не брать тему или имя из примера.
2. Сохранить `<рабочий-каталог>/models/<имя>.json`. Запустить:

       python3 <путь-к-business-modeling>/scripts/validate_idef0.py <путь-к-модели.json>

   Исправить ошибки, осмысленно разобрать предупреждения. Затем вручную
   проверить ICOM, единый словарь, баланс непосредственных детей, границы,
   обратные связи и полноту. Успех валидатора не доказывает правильный смысл.
3. Использовать доступные в среде браузерные инструменты. Открыть отдельную
   вкладку сайта, сохранив незавершенные модели пользователя. Сначала прочитать
   актуальный интерфейс; прежние селекторы служат ориентирами, а не гарантией.
   Вставить JSON в «ОПИСАНИЕ МОДЕЛИ» (ранее `#source`).
4. Выбрать «Ramus на Java» → «20 и новее» (ранее `#java`, значение `20`).
   Проверить выбранный вариант на экране, не оставлять Java 8 по умолчанию.
   Это вариант файла модели, не установка Java или программы Ramus.
5. Просмотреть каждую диаграмму: A-0, A0 и все раскрытия. Проверить сообщения
   сайта, названия, стороны и направления стрелок, баланс, туннели, читаемость,
   обрезку и пересечения. Исправлять исходный JSON, снова валидировать и
   импортировать. Если повторная конвертация дает ту же ошибку, описать ее
   и сохранить материалы; не повторять экспорт бесконечно.
   Сайт также предупреждает о длинном author в штампе (наблюдаемый ориентир
   около 22 знаков). Проверить штамп и при необходимости использовать фамилию
   с инициалами, сохраняя личность заданного автора; не заменять его примером.
6. Нажать «Скачать .rsf» (ранее `#download`), дождаться реального файла.
   Сохранить в `<рабочий-каталог>/models/<имя>.rsf`, проверить:

       python3 <путь-к-business-modeling>/scripts/check_rsf.py <путь-к-модели.rsf>

   Проверка ZIP/CRC подтверждает целостность контейнера, но не открытие в Ramus.
7. При доступном Ramus открыть файл и проверить уровни. Иначе явно сообщить,
   что открытие в настольном Ramus не подтверждено. Не выдавать альтернативную
   самодельную отрисовку за проверку сайта или экспорт Ramus.
8. Дать кликабельные ссылки на реальные `.rsf` и `.json`, только существенные
   замечания. При явно требуемом ответе строго JSON вернуть один JSON-объект
   без markdown, ссылок и объяснений; артефакты остаются в рабочем каталоге.

Если браузерных инструментов нет, сайт/экспорт недоступен или нет прав записи:
завершить доступную подготовку и проверки, сохранить JSON и назвать конкретное
ограничение. Не подменять отсутствующий `.rsf` переименованным JSON. При
необходимости дать точные ручные шаги как запасной путь, сохранив исходник.
Сам плагин не устанавливает браузерный коннектор. Локальные инструменты
браузера и разрешение скачивать файлы должны быть доступны в Codex.

В исходном проекте экспорт примера Java 20+ проверялся 11.10.2026. Это
историческое наблюдение; для каждой новой модели нужна новая проверка.
