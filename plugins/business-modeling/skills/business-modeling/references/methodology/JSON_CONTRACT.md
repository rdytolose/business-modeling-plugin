# Контракт JSON для сайта IDEF0

Источник: прямые требования пользователя от 11.10.2026. Сайт:
https://idef0.wakl3.com/. Проверен импорт встроенного примера и экспорт `.rsf`
с выбором Java 20+. Полная проверка всех вариантов связывания и туннелей
не выполнена. Порядок выдачи готовых файлов — `RAMUS_WORKFLOW.md`.

Корень: объект с `model` (непустая строка), `author` (непустая строка),
`activity` (объект контекстной работы). Не добавлять технические идентификаторы,
описания, стрелки отдельными объектами, координаты или сведения о проверке.

Каждая работа имеет `name` (непустая строка) и четыре массива строк:
`inputs`, `controls`, `outputs`, `mechanisms`. Пустой массив допустим только
для inputs и mechanisms. На каждой стороне максимум 6 уникальных непустых строк.
Ни одна строка не присутствует в inputs и controls одной и той же работы.

У декомпозированной работы есть `children`: массив из 3–6 работ той же структуры.
У листовой работы поля children нет; не использовать null и пустой children.
activity обязательно имеет children. Глубина определяется содержанием процесса.

## Имена и связи

Связи в конвертере, по словам пользователя, выводятся из точного совпадения
названий. Регистр, пробелы, е/ё, пунктуация и дефисы значимы. Не исправлять
одну подпись отдельно от остальных употреблений той же сущности.
Не использовать одинаковое имя для разных по смыслу объектов.
Имена работ уникальны во всем дереве, включая родителя и потомков.

Для каждой группы непосредственных children:
- каждый inputs родителя присутствует хотя бы в одном inputs ребенка;
- каждый controls родителя присутствует хотя бы в одном controls ребенка;
- каждый mechanisms родителя присутствует хотя бы в одном mechanisms ребенка;
- каждый outputs родителя присутствует хотя бы в одном outputs ребенка.

Это консервативный профиль совместимости: перенос между сторонами или
переименование ветви не использовать без подтвержденной поддержки конвертера.
Выход ребенка может стать входом, управлением или механизмом другого ребенка.
Обратные связи разрешены: порядок массива не задает временную последовательность.

Внутренняя связь между двумя детьми не является потерянной граничной стрелкой
только потому, что она не показана у родителя. Для дополнительной граничной
стрелки, которой нет у родителя и которую не дает соседний ребенок, пользователь
заявил автоматическое туннелирование. Валидатор сообщает такую ситуацию,
но сам сайт и графическое обозначение туннеля требуют отдельной проверки.
Не прятать туннелем необходимую связь или противоречие между уровнями.

## Проверка

`python3 scripts/validate_idef0.py models/model.json`

Код возврата 0: структурные проверки пройдены; 1: ошибки; 2: файл/JSON не прочитан.
`--strict` также отклоняет модели с предупреждениями, требующими ручного разбора.
Валидатор не исправляет строки автоматически. Отчет проверок не включать в JSON
готовой модели, который пользователь вставляет в сайт.

## Выдача через Ramus

По умолчанию модель сохранить и проверить как JSON, импортировать на указанный
сайт, экспортировать с выбором Java «20 и новее» и отправить `.rsf` вместе с
исходным `.json`. При явном требовании строго JSON текст ответа остается
одним JSON-объектом. Позднейшее предпочтение выдачи файлов закреплено
пользователем 11.10.2026 и уточняет первоначальный режим ответа.
