# Business Modeling — плагин для Codex

Восемь навыков с общей методикой и исходными материалами. Можно строить и
проверять IDEF0, UML, BPMN, IDEF3, eEPC, оргструктуру, деревья функций, DFD/WFD
и оформлять учебные отчеты. Каждый запрос начинает с адресного чтения правил
и нужных страниц источников. История исходного чата не требуется.

Для IDEF0: **описание → JSON → валидатор → проверка смысла →
idef0.wakl3.com → Java 20+ → все предпросмотры → .rsf + .json**.
Для остальных нотаций выбирается формат нужного редактора; экспорт через
сайт IDEF0 не применяется.

## Что нужно

- Codex desktop с поддержкой плагинов либо навыков; Codex CLI нужен для команд
  каталога. Их доступность может различаться по версии и среде.
- Python **3.11 или новее** для включенных скриптов; сторонние библиотеки не нужны.
- Для самостоятельной выгрузки IDEF0 — доступные Codex браузерные инструменты,
  сеть и скачивание файлов. Плагин сам не устанавливает браузерный коннектор.
- Для чтения источников — возможность читать/просматривать PDF. Для отчетов
  и некоторых форматов схем нужны соответствующие инструменты среды.
- Около 650 МБ для установленного комплекта и собранной книги; при наличии
  клона Git, его истории и кэша установки разумно иметь 1–2 ГБ свободного места.

Полный перечень и ограничения источников: [MATERIALS.md](MATERIALS.md).

## Установка друзьям из GitHub

Владелец сначала приглашает друга в закрытый репозиторий:
GitHub → репозиторий → Settings → Collaborators → Add people.
Друг принимает приглашение. Для GitHub нужны Git и GitHub CLI (`gh`).
В терминале друга:

```bash
gh auth login -h github.com
gh auth setup-git
gh repo clone rdytolose/business-modeling-plugin
cd business-modeling-plugin
python3 scripts/verify_package.py
codex plugin marketplace add .
```

На Windows вместо `python3` можно использовать `py -3.11`, если установлен
Python 3.11; при другой версии ≥3.11 использовать соответствующий запуск.
Для клонирования не вставлять токен в URL и не отправлять его в чат.

Перезапустить Codex desktop. Открыть каталог Plugins, выбрать источник
**Business Modeling Tools**, найти **Business Modeling** и нажать установку.
Плагин должен быть включен. Открыть новый чат в папке своей работы.
Названия пунктов могут отличаться в конкретной версии приложения.

Если приложение/CLI не поддерживает каталог плагинов, установить тот же набор
как обычные навыки из клонированной папки (без установки плагина):

```bash
python3 scripts/install_skills.py --destination ~/.codex/skills
```

В PowerShell:

```powershell
py -3.11 scripts/install_skills.py --destination "$env:USERPROFILE/.codex/skills"
```

Скрипт копирует все восемь навыков вместе с ресурсами и отказывается затирать
существующие навыки. Перезапустить Codex и открыть новый чат. Использовать
один способ установки, чтобы не получить два экземпляра навыков.

Если нет доступа к GitHub, распаковать полный ZIP. В терминале перейти в
папку `business-modeling-plugin` и выполнить те же команды проверки и локального
добавления каталога. Это тот же комплект со всеми доступными источниками.

## Как пользоваться

Навыки могут выбираться по запросу автоматически; для явного вызова:

| Навык | Задача |
|---|---|
| `$business-modeling` | Общий порядок и выбор нотации |
| `$idef0-ramus` | IDEF0, проверка и .rsf через сайт |
| `$uml-modeling` | Диаграммы UML |
| `$bpmn-modeling` | BPMN и проверка маршрутов |
| `$idef3-modeling` | Сценарии IDEF3 |
| `$aris-modeling` | eEPC, оргструктура и дерево функций |
| `$dfd-wfd-modeling` | DFD/WFD и карты процессов |
| `$modeling-report` | Оформление учебного отчета |

В установленном плагине интерфейс может показывать имена с префиксом плагина.
Выбрать нужный навык из списка, если короткое имя неоднозначно.

Первый запрос, с собственными данными вместо квадратных скобок:

```text
Используй $idef0-ramus. Процесс: [название]. Автор модели: [имя].
Состояние: [как есть/как должно быть]. Вот описание: [описание и документы].
Построй модель по методике, проверь JSON и все диаграммы, выгрузи через
idef0.wakl3.com для Java 20+ и дай .rsf вместе с исходным .json.
```

Книгу агент собирает самостоятельно при первом обращении в записываемой папке
работы. Ее точный оригинал входит в пакет в частях, каждая проверяется по SHA-256.
Процесс, автор, организация и разрешения исходного пользователя не переносятся.
Установка не заменяет проверку каждой новой модели и не дает доступа к Лань.
В папке основного навыка `examples/` есть явно учебный JSON и соответствующий
экспорт сайта `.rsf`. Их тема и поле «Учебный пример» не являются данными
пользовательской работы. При тестировании пакета импорт и скачивание Java 20+
прошли, ZIP/CRC проверены; захват снимков предпросмотра был недоступен, поэтому
полная визуальная приемка примера и открытие в настольном Ramus не подтверждены.

Для проверки установки попросить: «Используй $business-modeling, найди
в комплекте правила IDEF0 и перечисли этапы экспорта, ничего не рисуя».
Агент должен прочитать локальные правила и назвать Java 20+, проверку JSON,
всех предпросмотров и выдачу двух файлов. Если навыки не видны, проверить
включение плагина, перезапуск приложения и новый чат.

## Обновление

В клоне выполнить `git pull --ff-only`, затем
`codex plugin marketplace upgrade business-modeling-tools`.
Перезапустить приложение и обновить/переустановить плагин, если его установленная
копия не обновилась: Codex загружает копию из кэша, а не исходную папку.
Для обычных навыков сначала сохранить собственные изменения; установщик
намеренно не обновляет и не удаляет существующие папки.

## Как владельцу загрузить на GitHub

Выполнять **только внутри этой подготовленной папки**, а не в исходном проекте
с личными моделями. Репозиторий должен оставаться закрытым для данного комплекта.

```bash
gh auth login -h github.com
gh auth setup-git
git init -b main
git add .
git commit -m "Add business modeling plugin and source materials"
gh repo create business-modeling-plugin --private --source=. --remote=origin --push
```

Если репозиторий уже опубликован, повторно его создавать не нужно. Результат
команды/фактический URL нужно проверить, прежде чем давать друзьям ссылку.
Ни один распространяемый файл не превышает 25 МиБ. Книга разделена на части
по 24 МиБ: Git LFS для этого комплекта не требуется. Не добавлять собранный
284-МБ PDF из папки `.business-modeling-materials` в Git.

Формат каталога и команды сверены с
[официальной документацией OpenAI](https://developers.openai.com/plugins/build/plugins).
Лимиты файлов: [документация GitHub](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).
Локальная проверка пакета не доказывает установку в приложении каждого друга,
открытие в настольном Ramus или исправность браузерного коннектора его среды.
